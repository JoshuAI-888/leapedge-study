# Retrieval date and source readiness

Fresh retrieval requests now use the configured primary-domain registry as a search allowlist when it is nonempty. The returned record explicitly warns that the registry can miss unlisted issuers and is not exhaustive verification. Provider-returned hosts still undergo exact hostname/subdomain matching; the request filter cannot itself promote a source. No trusted domains were added.

Current-update requests accept an optional `since` ISO timestamp, strictly before their cutoff and only for current mode. It becomes Exa's `startPublishedDate`, the durable paid-request identity, the speculative retrieval identity and the version 2 shared-cache identity. A different interval cannot reuse a donor from a wider interval. Existing no-since paid identities remain unchanged, including unknown outcomes; v1 records remain readable, but cannot donate into the new shared-cache policy. Final source eligibility still has to enforce the time boundary independently.

Publication confirmation requires an explicit line-start publication/release/filing label in retained source text agreeing with the provider date. ISO dates, SEC's next-line Filing Date, abbreviated English months, ordinals and day-month-year forms are accepted. An updated date, reporting period, incidental sentence about another publication, mismatched date, malformed calendar date or estimated date alone is insufficient. Confirmation remains conservative end-of-day, not an invented intraday timestamp. The original text and its hash are unchanged. Confirmed publication date never means a factual assertion is corroborated.

The Exa API options were checked against the provider's [search reference](https://github.com/exa-labs/agent-skills/blob/main/skills/build-with-exa/references/search.md). No live Exa/model calls were made for this change.

Validation: two new behavioural tests first failed on missing SEC/date-format support and missing `startPublishedDate`. All nine retrieval tests then passed in both default and PGlite modes, including request preservation, unknown billing outcomes, exact cutoff/domain/query cache isolation, expired caches, malformed calendar dates, source text preservation and interval validation. Typecheck passed at integration checkpoint. Existing prefetch test expecting an empty final brief to complete must align with the separate readiness changes; this is not a retrieval failure.

Limitations: a page containing an inaccurate explicit publication label can still mislead date attribution. This parser does not independently authenticate a publisher or fetch SEC structured filing metadata. Source registry completeness and quality gains require source-backed live evaluation; no retrieval hit-rate, quality or speed improvement is asserted from fixtures.
