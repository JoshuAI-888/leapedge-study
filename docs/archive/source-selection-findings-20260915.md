## Hypothesis and intervention

Selecting source segment IDs and copying their text in application code should eliminate quotation retyping errors without relaxing exact matching. An explicit instrument inventory should surface omitted substantive views. Neither intervention proves the retained transcript matches audio or that interpretations are supported.

Candidate `evidence-first.web.v8-source-selection-candidate` preserves v7 fidelity instructions, replaces generated quotation strings with `evidence_segment_ids`, and requires a source-linked inventory. `materializeSelectedClaim` rejects unknown and duplicate IDs, copies entire selected cues without normalization, and leaves per-quote English translations empty. Synthesis remains English. Existing number/ticker validation and model critique run after materialization. This is an experimental adapter, not wired into the production pipeline or selected by default.

The audit is batched once per video with exact output-ID coverage validation and a model omission check. v7 used individual claim audits. Therefore this is a comparison of pipeline variants, **not a controlled prompt-only A/B test**. Whole-cue context may make checks easier, while batching may miss fine-grained errors. An inventory marked represented is not independently verified completeness.

## Independent accuracy method

`docs/blind-audio-review.html`, generated by `scripts/build-blind-review.py`, contains only the nine preselected windows and instructions—not candidate transcripts or model answers. Total audio duration is 9m28s. It opens timestamped YouTube links, stores draft notes locally when available, and downloads a portable JSON document. No network write, API key or candidate answer is embedded. Browser inspection confirmed nine sections, a zero-completed initial state and functioning local-storage status.

The reviewer records original spoken text, critical facts, timing landmarks and uncertainties before candidate exposure. Listening attestation alone is not silently converted into verified benchmark data: exported rows remain pending until notes, boundaries and annotations are validated. Inaudible sections must remain uncertain. English WER / Chinese CER, critical-fact matches and timestamp errors will use the existing `evaluations/transcript-accuracy.ts` evaluator once compatible annotations are present. Empty annotations are unmeasured, not perfect scores. Candidate excerpt boundaries require review; whole captions cannot be guessed into clipped audio windows.

These are development windows. After correcting known failures, select and freeze new English, Chinese and captionless cases **before examining candidate outputs**. Record source accessibility and caption status at test time. Compare LeapEdge and our output against the same independently heard source, with separate omission, unsupported-claim, numeric-role, condition and timestamp measures. A model's assertion of no omissions is not a recall denominator. No fresh held-out videos or independent listening scores were produced in this run.

## Documentation and remaining risks

Google's [structured-output documentation](https://ai.google.dev/gemini-api/docs/structured-output), revisited for this run, describes schema-constrained output. Our harness uses JSON MIME plus runtime Zod validation; it does not claim provider-enforced schema validation for these text calls. Schema validity cannot establish semantic fidelity. The earlier SDK fetch-failed report remains a similar symptom, not a confirmed cause of the Mandarin v7 failure (see the completion white paper).

Whole-cue selection may increase quote length and provide unrelated surrounding words; exact copying is deliberately not an entailment test. Per-quote translation remains absent in this candidate and must be handled before product parity. Model batch critique missed a numeric-role error and qualifier loss. Independent review and held-out comparisons remain necessary before any claim of superiority over LeapEdge.
