## Actual processing path

1. Discovery uses YouTube metadata/uploads, optional push and opt-in channel monitoring. `research-store.ts:450` freezes workspace models, prompt and origin into run input; explicit mode overrides origin defaults. Defaults in `settings.ts:135` are manual immediate, channel batch. Historical replay explicitly sets batch (`replay.ts:146`). `channels` discovery permission and automatic paid processing are separate controls.
2. `store.create` inserts a deduplicated run and `analyze` job atomically. Queue admission uses a short advisory capacity lock plus `FOR UPDATE SKIP LOCKED`, leased ownership tokens, reserved manual capacity and bounded drains. Vercel `after()` and cron call the existing runner, rather than a second scheduler. Serving DB is Supabase per October deployment updates; the old Neon/Mac text is stale. Actual hosted settings were not fetched or changed during this isolated experiment.
3. `pipeline.ts:1129` uses supplied timed source or `standbyTranscript`. `transcripts.ts` normalizes TranscriptAPI captions and Supadata native/generate responses, tracks caption credits and vendor circuits, and contains a Supadata batch adapter. The current replay/channels code does not call that adapter; it is intended groundwork rather than active coalescing. Caption-vendor batching is unrelated to Gemini Batch. A missing-caption response does not automatically buy standby generated speech unless explicitly permitted.
4. Missing/questionable coverage routes to `windowed-asr.ts` through `modelCall`, with forced native Google, fixed offsets, LOW resolution, gap inspection, bounded subdivisions and checkpoints. Imported sources must pass Source validation. Generated timestamps are never independent speech alignment. `native-google.ts` is a separate, kill-switched legacy whole-video experiment through `native-google-core.ts`, not the normal windowed path and not the batch transport.
5. Extraction (`synthesis`/`synthesis-chunk-*` stage names) returns pointer ranges. Exact source bytes, hashes and prompts are retained. Deterministic checks copy evidence, reject invalid pointers, bound source coverage, resolve identities without rewriting literal quotes and preserve doubts. Some extraction fanout uses bounded parallel calls; that is synchronous concurrency, not provider Batch grouping.
6. Translation consumes copied evidence spans and preserves original-language hashes. Critique audits claims, key points and mentions together in output-aware chunks. `assertCriticIndependent` checks the configured family; default Sonnet 5 uses OpenRouter while native Gemini handles extraction/translation/media. Google-only configurations may explicitly relax family independence; the experiment does not. Cheaper Inference exists for explicitly configured text routes, rejects media, and is not Gemini Batch eligible. OpenRouter fallback is configuration-dependent, not permission to bypass unknown bills.
7. Root publication applies deterministic/trust checks, source-range integrity and critique outcomes. The research child performs source-backed synthesis, faithfulness/audit, numeric, attribution, semantic-basis, coverage and final publication/readiness checks, with bounded independently audited repairs where configured. Web research is on-demand or explicitly experimental. Checked findings and final reviewed publication are distinct checkpoints. A rejected or unavailable audit cannot be converted into accepted output to save cost.

## What the batch implementation actually does

`pipeline.ts:508` chooses Batch whenever run input says `batch` **and** the selected transport family is `google-native`; it does not exclude video. The same GenerateContent parameter builder serializes text and `video.fileData`, offsets, system instructions, thinking and schemas. `batch.ts:180` sends `src: [one request]`, so every native stage/window/chunk creates its own provider job. It does not execute a graph, coalesce videos, upload JSONL, or batch non-Google critics. Supadata batches and multi-item critique prompts are independent concepts.

Submission intent and discounted reservation share one DB transaction before I/O (`batch.ts:148`). A stable hash of run/stage/request fingerprint becomes the record ID and metadata key. A resource name is persisted with a `batch-poll` job after creation. The 19 MiB request guard leaves envelope margin below Google's 20 MB limit. Provider SDK retries are disabled; creation has a 60-second timeout. An ambiguous submission stays submitting/uncertain, retains the budget and never automatically resubmits. The advisory budget lock, run row lock and unique open-attempt/attempt indexes prevent concurrent double billing; eight real concurrent attempts created one intent in this experiment.

`pollBatch` is read-only at Google and selects by exact metadata key, never array position. Temporary read failures raise `BatchPending`; malformed, duplicate or terminal-missing outputs require reconciliation. Valid output, raw response, normalized replay and settlement are saved atomically. Failed keyed requests release their holds under existing behavior; cancellation/expiry without the keyed result retains uncertain commitments. Generic synchronous reconciliation explicitly excludes batch commitments. Result parsing/STOP checks and caller Zod validators remain above the transport.

The runner treats BatchPending as queued, checkpoints the analysis and schedules another attempt after 60 seconds. `batch-poll` also retries after 60 seconds on temporary status errors. Poll completion is consumed by a subsequent analysis job replaying the same fingerprint. Worker leases are ten minutes and renewed every minute. Real checks killed a worker after simulated provider acceptance, reclaimed its lease from another process, fenced the old token and refused a duplicate submission. This proves local real-Postgres behavior with a mocked provider, not an actual paid worker crash.

## Documentation drift

AGENTS.md/spec/build-loop describe Neon, Mac/always-on hosts and an “always-on worker”; October deployment docs and serving configuration use Vercel Functions + Supabase. README/.env.example still say cron disabled while channel-monitoring docs describe an enabled 15-minute heartbeat and `vercel.json` defines that schedule. Deployed flags were not inferred from either. Code gates above are authoritative for execution prerequisites; operator verification of deployed flags remains required. The spec's low-resolution “removes frame tokens,” generic “halves model spend” and asserted timing-gate language overstate current evidence. Old source-atom and gold artifacts are diagnostics; none are independent speech ground truth. This audit records drift without relabeling old outcomes as current production acceptance.
