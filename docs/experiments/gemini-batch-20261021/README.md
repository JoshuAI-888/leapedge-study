# Gemini Batch investigation — 21 October 2026

**Decision: no production promotion. Keep manual processing synchronous; continue only an explicitly enabled text-backfill experiment after billing, servicing and quality prerequisites. Batch video remains unverified after a rejected request.** Draft PR [#46](https://github.com/JoshuAI-888/leapedge-study/pull/46), branch `experiment/gemini-batch-20261021`, baseline `32a65994dcdd31f1e2caf1e86db2afaa75549c7b`. No deployment, production/default change, automatic monitor, new dependency or migration.

Nine live generation requests completed across three existing financial videos: three synchronous 0–30s YouTube intervals, three frozen-transcript controls, and three matching text batches. One Batch media request rejected 400 before a job name; its exact provider detail was lost by the old adapter, so the media branch stopped without a workaround. These are token-derived prices, not invoice-confirmed all-in bills; caption/infra costs are not silently zero.

All six extraction outputs passed Zod and exact source-pointer resolution. Text Batch cost 49.98–66.90% less at that stage, with first observed results 149–259s versus synchronous12.5–15.2s. The high Planet reduction includes a 9,030-token cache hit, and generated output lengths differ. Both Planet outputs reconstructed unsupported guidance from ambiguous captions; the existing numeric gate marks it unresolved. Source/prompt/schema/model identity is checked, but independent speech accuracy, timestamp alignment, full research fidelity and15% all-in saving are **not established**. No p95 or scale claim is made from three cases.

The existing implementation already has one paid request per provider job, durable intent/reservation/resource name/keyed result handling, leased polling and replay. Small regression-driven repairs preserve unknown billing on incomplete usage/replay, retain sanitized rejection diagnostics, mark malformed outputs uncertain, and validate new model/window/cache admissions before paid I/O. Real isolated Postgres checks include eight concurrent submissions, a worker killed after simulated acceptance, lease recovery and stale-owner fencing. Existing independent critique/publication constraints remain unchanged.
